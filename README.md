# NIIGO

家庭のタスクを Google Sheets と Web 画面から編集するアプリです。1つのスプレッドシートが1つの Space に対応します。Google Sheets が保存先であり、Sheets 上の編集内容も Web 画面に反映されます。

## 構成

- `web/` はブラウザで動く JavaScript の画面です。シートの列位置やセルのメモを意識せず、Task、Round などのデータとして扱います。
- `server/` は Web 画面の API と Google Sheets の読み書きを担当します。画面から Google の認証情報を扱いません。
- `apps-script/` はシート内の ID 付与、入力規則、担当者選択、ラウンド終了を担当します。Web 画面の配信には使いません。

## Google Sheets と Apps Script の準備

作成済みの シート には、4タブと Apps Script プロジェクトを配置済みです。シートを開き直して「NIIGO → 初期設定」を一度実行し、権限を承認してください。メニューが見えない場合は「拡張機能 → Apps Script」から `setup()` を実行します。この操作で編集トリガーと入力規則を設定します。

新しい Space を作る場合は、空のスプレッドシートに `apps-script/` の3ファイルを紐付けた Apps Script プロジェクトとして配置し、同じ初期設定を実行します。`clasp` を使う場合は `.clasp.json.example` を `.clasp.json` にコピーして、紐付けられたプロジェクトの ID を設定します。`clasp push` は `apps-script/` だけを反映します。

サービスアカウントによるデプロイ時更新の要件と検証結果は [Apps Script のデプロイ時更新に関する検証](docs/apps-script-deploy-feasibility.md) にまとめています。この方式はまだ実装していません。

## Web 画面をローカルで起動

1. `npm install` を実行します。
2. `.env.example` を `.env` にコピーし、`NIIGO_SPREADSHEET_ID` に対象のスプレッドシート ID を設定します。
3. Google Sheets API を利用できるサービスアカウントを用意し、そのメールアドレスに対象シートの編集権限を付与します。認証情報の JSON 全体を1行にして、`.env` の `GOOGLE_SERVICE_ACCOUNT_JSON` に設定します。秘密鍵の改行は JSON 内で `\n` のまま保存してください。鍵を Git に追加しないでください。
4. `npm run dev` を実行し、`http://127.0.0.1:3000` を開きます。`npm start` でも同じように起動できます。

サーバーはローカルホストで待ち受けます。家庭内で Web 画面を共有するための認証と公開方法は、まだ決めていません。公開する際は利用者の認証と Sheets への権限を設定する必要があります。

## シートでの操作

`Tasks` の担当者には、メンバー名をカンマで区切って直接入力できます。複数選択の画面は「NIIGO → 担当者を選択」から開きます。対象のタスク行を選択してから使ってください。

ラウンドを終了するときは「NIIGO → ラウンドを終了」を使います。未完了のタスクごとに次のラウンドまたは Backlog を選択できます。`Rounds.status` を直接 `Closed` に変更した場合は元に戻し、この操作へ案内します。列を移動した後は「NIIGO → 入力規則を更新」を実行してください。

## 採用した設計

- セルには参照先の名前を表示し、セルのメモに `NIIGO:["id"]` 形式で ID を記録します。担当者は複数 ID を記録します。名前の重複は許さず、名称変更時は ID を手掛かりに表示名を更新します。メモを消した場合は、重複のない表示名から参照を復元します。
- ID は UUID です。Web 画面からの追加時と、Sheets で行を編集した時に付与します。欠損や重複を検出した場合は Web 画面の読み書きを止めます。コピーした行の ID は自動変更しません。
- Task の初期ステータスは `Todo`、Round は `Planned` です。Task の名前以外の項目と Round の日付は空欄を許します。日付を入力する場合は `YYYY-MM-DD` とし、Round の終了日は開始日以降にします。進行中の Round は1件までです。
- Web 画面で保存する際は、読み込んだ行の内容と保存直前の内容を照合します。食い違う場合は再読み込みを求めます。行と列は保存直前に ID と見出しから探し直します。
- ラウンド終了時は未完了 Task ごとに移動先を指定します。次の Round がない場合も Backlog を選べます。完了 Task と期限は変更しません。
- ID 列は初期状態で最右に置き、非表示にして編集時の警告を設定します。タブと必須見出しの名前は変更しないでください。独自列は保持します。

## 制限

編集トリガーは Sheets の通常のセル編集で動作します。外部 API や別のスクリプトによる変更では動作しないため、その経路で行を追加した場合は ID や参照メモを別途整える必要があります。複数セルを同時に貼り付けてラウンドを `Closed` にする操作では、終了時の移動先選択を行えません。

Web 画面の削除、検索、並べ替え、絞り込みは実装していません。Sheets の変更と Web 画面からの保存が同時に起きた場合、保存直前の再読込後の変更までは検出できません。

`npm test` で保存処理を検証できます。
